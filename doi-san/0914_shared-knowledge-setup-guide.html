これで何ができるようになるか

土居さんのMacのデスクトップに 共有ナレッジフォルダ ができます。
過去のInstagram投稿・YouTube・講義の文字起こし・SEO記事などが全部入っていて、
Claude Code に「あのフォルダ見て」と言うだけで、全部読んで答えてくれる状態になります。
Honoka 側がナレッジを更新すれば、土居さん側にも反映されます。

PART 1

招待を承認する

GitHubアカウントの作成は完了済みなので、ここからです。

1招待ページを開く

GitHubにログインした状態で、下のアドレスを開いてください。

https://github.com/honokamorohashi/doi-knowledge/invitations

緑色の Accept invitation を押せば完了です。

メールからでも承認できます

GitHubから届いている英語のメール内の「View invitation」からでも同じ画面に行けます。メールが見つからない場合は上のURLを直接開いてください。

有効期限は7日間です

過ぎてしまった場合は Honoka に再送を依頼してください。

PART 2

MacをGitHubにつなぐ

Claude Code に作業してもらいます。コマンドを覚える必要はありません。

1下の文章をそのまま Claude Code に貼り付ける

COPY & PASTE
GitHubに接続できるようにしたいです。以下をお願いします。 1. Homebrew が入っていなければインストール 2. GitHub CLI（gh）をインストール 3. gh auth login でブラウザ認証（HTTPSで） 4. gh auth setup-git を実行 5. git の user.name と user.email を設定 user.name は「土居正英」、user.email は GitHub に登録したメールアドレスを使ってください。
途中でMacのパスワードを求められることがあります

Homebrew のインストールに管理者権限が必要なためです。ご自身のMacのログインパスワードを入力してください。

2ワンタイムコードを入力する

画面に XXXX-XXXX という8桁のコードが表示され、ブラウザでGitHubのページが開きます。そのコードを入力して Continue を押してください。

3認可する

Authorize GitHub CLI の画面で、緑色の Authorize github を押してください。

緑のボタンが押せないとき

GitHubは誤クリック防止のため、ボタンを数秒間ロックしています。ページの余白をどこか1回クリックして、5秒ほど待ってから押してみてください。

「Authentication complete.」と出れば成功です
PART 3

フォルダを取ってくる

GitHub上にあるフォルダを、そっくりそのまま自分のMacにコピーします。この作業は初回の1回だけです。

「clone（クローン）」とは

GitHubに置いてあるフォルダを、中身ごと丸ごとダウンロードして自分のMacに実体として作ることです。ダウンロードに近い作業ですが、フォルダ構造も更新履歴もそのまま引き継がれます。

【実行前】 デスクトップには何もない ↓ コマンドを1回実行（約10〜30秒） 【実行後】 デスクトップに doi-knowledge フォルダが出現（739ファイル）

1Claude Code を開く

いつも使っている Claude Code を開いてください。このときの作業フォルダはどこでも構いません。「デスクトップに作って」と指示するので、いまどこを開いていても正しい場所に作られます。

2下の文章をそのまま貼り付けて送る

COPY & PASTE
下のリポジトリをデスクトップに clone してください。 https://github.com/honokamorohashi/doi-knowledge.git

コマンドを自分で打つ必要はありません。この日本語を貼るだけで、Claude Code が裏で処理してくれます。

3実行の確認が出たら「許可」を押す

Claude Code が「このコマンドを実行してよいか」と聞いてくることがあります。表示されるのはこのようなコマンドです。

git clone https://github.com/honokamorohashi/doi-knowledge.git

内容を確認して 許可 を押してください。

410〜30秒待つ

34MBほどのデータをダウンロードします。「完了しました」という返事が来るまで待ってください。

5Finderでフォルダができたか確認する

デスクトップを見てください。doi-knowledge という名前のフォルダができています。開くと中身はこうなっているはずです。

doi-knowledge/ ├── 01_ナレッジ/ ├── 02_SEO/ ├── 03_note・アメブロ/ ├── 04_X・Threads/ ├── 05_YouTube/ ├── 99_コラボ/ └── 各種管理シート（.xlsx）
これが見えたらダウンロードは成功です

普通のFinderのフォルダなので、開く・コピーする・編集する、すべていつも通りできます。

6Claude Code の作業フォルダをここに切り替える

ここが一番大事な工程です。 フォルダができただけでは、Claude Code はまだそこを見ていません。

Claude Code で 新しいセッションを開き、作業フォルダにデスクトップの doi-knowledge を指定 してください。これで初めて、Claude Code がこのナレッジを読める状態になります。

切り替えを忘れると「ファイルが見つかりません」と言われます

フォルダは確かに存在しているのに読めない、という場合はほぼこれが原因です。

7本当に読めるか確認する

作業フォルダを切り替えたセッションで、下を貼ってみてください。

COPY & PASTE
01_ナレッジ/01_Instagram を読んで、 私が繰り返し話しているテーマを5つ挙げてください。
過去のInstagram投稿をふまえた答えが返ってきたら、すべて完了です

ここまで来れば、あとは自由に使えます。

ここからが本題です
PART 4

フォルダの中身

何がどこにあるかの地図です。媒体ごとのデータが先頭に並んでいます。

doi-knowledge/ │ ├── 01_ナレッジ/ ← 素材の本体 │ ├── 01_Instagram/ 過去の投稿・リール・ライブの文字起こし │ ├── 02_YouTube/ 動画の文字起こし │ ├── 03_Threads/ Threads投稿 │ ├── 04_講義・セミナー/ グループ講義・勉強会の文字起こしと資料 │ ├── 05_商品・特典/ 講座商品資料・特典・FBグループ │ ├── 06_アウトプット/ 整形済みの文字起こしまとめ │ ├── 07_統合ナレッジ/ 全部を1ファイルに統合したもの │ ├── 08_アイデアプール/ 企画の種 │ ├── 09_おさる式メソッド/ 攻略本11冊 │ └── 10_クローラー定義/ 収集設定 │ ├── 02_SEO/ SEO記事のブリーフ・原稿 ├── 03_note・アメブロ/ note／アメブロ原稿 ├── 04_X・Threads/ X投稿 ├── 05_YouTube/ YouTube企画書 ├── 99_コラボ/ コラボ関連 └── 各種管理シート（.xlsx） コンテンツカレンダー・投稿管理表など
動画・音声・画像・PDFは入っていません

容量が大きいため、それらは従来通り Googleドライブでやりとりします。このフォルダに入っているのは文字（テキスト）のデータです。だからAIが全部読めます。

PART 5

Claude Code での使い方

Claude Code でこのフォルダを開いて、日本語で話しかけるだけです。

1まずこれを試してください

動作確認を兼ねた、一番わかりやすい例です。

COPY & PASTE
01_ナレッジ/01_Instagram を読んで、 私が繰り返し話しているテーマを5つ挙げてください。

過去のInstagram投稿を全部読んだ上で答えが返ってきたら、成功です。

■ 過去の発信を掘り起こす

「01_Instagram の過去投稿から、税金について話しているものを全部出して」

キーワードで横断検索します。何年前の投稿でも見つかります。

「このフォルダ全体から『イギリス』に関する発言を集めて、主張を整理して」

媒体をまたいで、発言の一貫性や変化を確認できます。

■ 企画を考える

「YouTubeの文字起こしを読んで、まだ記事にしていないテーマを5つ挙げて」

02_SEO の既存記事と突き合わせて、穴を探します。

「08_アイデアプール を見て、今月やるべき企画を3つ選んで。理由も教えて」

「09_おさる式メソッド のショート動画攻略本に沿って、リール台本を1本書いて」

メソッドを読ませた上で書かせる、という使い方ができます。

■ 原稿・コンテンツを作る

「04_講義・セミナー の文字起こしから、受講生がつまずいているポイントを抽出して」

「過去のライブで話した内容をもとに、Threadsの投稿を5本書いて」

口調や言い回しも過去データから学習するので、本人らしい文章になります。

コツは「どのフォルダを見てほしいか」を最初に言うことです

フォルダ名を指定すると、そこを重点的に読んでくれます。指定しなくても探してくれますが、指定した方が速くて正確です。

毎日

覚えることは2つだけ

Googleドライブと違い、自動では同期されません。取りに行って初めて最新になります。

作業を始めるとき
「最新を取ってきて」

Honoka側の更新が反映されます。これをやらないと古い情報のまま作業することになります。

作業を終えるとき
「変更を共有して」

土居さん側の変更が Honoka に届きます。これをやらないと相手に伝わりません。

注意

気をつけていただきたいこと

項目内容
非公開ですPrivate設定です。招待された人しか見られません。インターネットに公開されることはありません。
パスワードやAPIキーは置かない絶対に入れないでください。共有されてしまいます。
.git フォルダは触らないフォルダ内の .git は履歴の本体です。移動・削除しないでください。通常はFinderに表示されません。
同時に編集しても壊れませんお互いが別のファイルを触った場合は自動で統合されます。同じ箇所を触った場合だけ確認を求められます。どちらかが消えることはありません。
困ったら

よくあるつまずき

「コマンドラインデベロッパツールをインストールしますか」という画面が出た

Macに開発ツールが入っていない場合に出ます。インストールを押して完了まで待ってください（5〜10分）。終わったら Claude Code に続きを頼んでください。

緑の Authorize ボタンが押せない

GitHubの誤クリック防止ロックです。ページの余白を1回クリックして5秒待つと押せるようになります。それでもダメなら、ページを閉じて Claude Code に「認証をやり直して」と伝えてください。

ワンタイムコードの有効期限が切れた

コードは15分ほどで無効になります。Claude Code に「もう一度認証して」と伝えれば新しいコードが出ます。

招待が見つからない

GitHubにログインした状態で https://github.com/honokamorohashi/doi-knowledge/invitations を直接開いてください。メールを探さずに承認できます。

デスクトップにフォルダができない

まず Claude Code の返事を確認してください。エラーが出ていればその内容を Honoka に送ってください。よくある原因は次の2つです。

① 招待をまだ承認していない → PART 1 に戻って承認してください。

② 認証が終わっていない → PART 2 に戻って「Authentication complete.」まで完了させてください。

「Repository not found」「Permission denied」と出る

このリポジトリは非公開のため、招待の承認とGitHub認証の両方が済んでいないとアクセスできません。どちらかが抜けている可能性が高いです。PART 1 と PART 2 を確認してください。

フォルダはあるのに「ファイルが見つかりません」と言われる

Claude Code の作業フォルダが doi-knowledge になっていない可能性が高いです。PART 3 のステップ6を確認してください。新しいセッションを開いて、作業フォルダにデスクトップの doi-knowledge を指定し直してください。

フォルダの中身が古い気がする

Claude Code に 「最新を取ってきて」 と伝えてください。自動では更新されません。

Claude Code を使わず、自分でコマンドを打ちたい

初回セットアップ：

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)" brew install gh gh auth login --web --git-protocol https gh auth setup-git git config --global user.name "土居正英" git config --global user.email "GitHubに登録したメールアドレス" cd ~/Desktop git clone https://github.com/honokamorohashi/doi-knowledge.git

日常の操作：

cd ~/Desktop/doi-knowledge git pull # 最新を取ってくる git add -A # 変更を共有する git commit -m "更新内容をひとこと" git push
ご不明な点があれば Honoka までお気軽にご連絡ください。
つまずいた画面のスクリーンショットをいただければ、そのまま確認いたします。
